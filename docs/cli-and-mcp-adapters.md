# CLI 与 MCP 适配器

HuAHua 手机端始终只暴露同一套受限局域网协议：配对、可信主机挑战、屏幕观察和带 observation id 的动作。电脑侧的 MCP 与 CLI 都是这套协议的适配器，不能分别实现配对、发现或安全会话。

## 共享会话核心

`DeviceSessionManager` 负责首次配对与后续恢复：

- 首次配对读取短时连接卡、创建或读取本机 P-256 身份、等待手机批准，并仅在成功后保存设备发现信息。
- 后续恢复通过 mDNS 找到当前手机地址，用已保存的主机私钥完成挑战签名，再换取短期令牌。
- 访问令牌只存在于当前进程内，不写入磁盘。主机私钥和设备发现信息由现有受限权限存储保存。

## 两个调用入口

- `huahua-mcp` 保持兼容：`connect` 与 `serve --device` 都通过共享会话核心创建 MCP stdio 服务。
- `huahua` 提供一次一进程的 CLI：`pair`、`observe` 和 `command`。每条 `observe` 或 `command` 自动恢复短期会话，不需要再次发送连接卡或在手机确认。

CLI 以 JSON 输出。观察可通过显式输出文件参数写出图片，方便具有本地文件视觉能力的 AI 读取；动作必须带本次观察返回的 id。

## 通用 Skill

包内的 `skills/huahua/SKILL.md` 只描述安全工作流和 CLI 命令，不实现另一套协议。支持终端但不支持 MCP 配置的 AI 可以读取它；纯网页聊天 AI 因无本地终端和局域网权限，不能直接控制手机。

## 安全边界

CLI 不提供 Shell、ADB、文件系统、通知、联系人或常驻公开端口。它仅调用手机既有的观察和有限动作接口，并保留首次手机批准、短期会话、可信主机签名、敏感操作交接和 observation id 前置条件。
